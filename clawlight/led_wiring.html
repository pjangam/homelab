Clawlight LED Wiring

One 3-leg red/green LED, two resistors and three header pins in the bottom corner of the Pi. The one thing that matters most: a resistor on each colour leg, never one on the shared leg — otherwise amber, the colour that means “don’t believe me”, cannot be mixed.

The whole circuit

Everything runs at the Pi’s 3.3V GPIO level. Each die gets its own pin and its own resistor; both dies return through the long leg to ground on pin 39. There is no 5V anywhere in this circuit.

LED legConnects toWhy it matters
red 220R → pin 33 · GPIO13 (3.3 − 2.0V) / 220Ω ≈ 5.9mA. Well under the ~16mA a Pi pin should source, and bright enough for a desk light.
green 220R → pin 35 · GPIO19 Yellow-green die (~2.1V): ≈5.5mA, matches red. Pure/emerald green die (~3.0V): only 0.3V left across the resistor, ≈1.4mA — swap in 100R for ≈3mA.
long leg pin 39 · GND No resistor here. It returns both dies’ current, ≈11mA with both fully on.

The driver matches this exactly: PINS = {"red": 13, "green": 19} and COMMON_ANODE = False in scripts/clawlight/clawlight-led.py. Pins are BCM numbers in the code, physical numbers on the board — count the physical ones.

Which leg is which

The long leg is settled: you confirmed on the bench that it is the common cathode. What the part itself does not tell you is which of the two outer legs is red. Find out with the Pi, one resistor and two jumpers, before anything is soldered.

  1. Find the longest leg. On this part it is the common cathode (confirmed on the bench 2026-09-16). It goes to GND and never gets a resistor.
  2. Jumper pin 39 to the long leg, and pin 1 through a 220R to one outer leg. Clip leads or a breadboard, no solder. Count pins from the square pad, pin 1, at the end away from the USB ports.
  3. Note the colour, then move the resistor to the other outer leg. One should glow red and the other green. Write down which side of the flat edge red is on — the flat edge is the orientation mark that survives after the legs are trimmed. Which colour sits beside it varies between makers, so it has to be read off this part, not assumed.
  4. If neither outer leg lights, check the jumpers first. If they are right, the LED is common anode after all: the long leg would go to 3.3V and the code needs COMMON_ANODE = True. Stop and re-plan before soldering; this page assumes common cathode.

The green resistor

The same test tells you which green you have. If the green leg glows a yellowish green about as bright as red, it is a ~2.1V die and 220R is right. If it glows a cool, bluish green that looks clearly dimmer than red, it is a ~3.0V pure-green die and gets 100R instead — at 1.4mA it would lose every amber mix to red.

One resistor per colour leg, never on the long legA single resistor on the shared cathode looks tidier and lights each colour fine on its own. The moment both are on, red’s lower forward voltage takes almost all the current and green barely glows, so amber comes out plain red. Idle and the unknown pulse both depend on that mix.

Pin 37 stays emptyThe earlier RGB plan put blue on GPIO26, pin 37, right between the two wires you need. Nothing drives it any more. A jumper left there from an old breadboard layout does nothing, but it is the easiest wire to plug a colour leg into by mistake.

Tune amber with the diffuser onThe optional ping-pong ball (in the parts list) blends the two dies into one colour instead of two points of light. It also shifts how the mix reads, so set AMBER after the ball is fitted, not before.

Verify in this order

Each check isolates one fault, so a failure tells you where to look. Run the deploy script from xero.

  1. Dry run, before the LED matters. This proves the credentials and the MQTT path with no GPIO involved. Expect server availability: online followed by a state=… -> rg(…) line. Ctrl-C to stop. 
    scripts/clawlight/deploy_clawlight_led_pi.sh --dry-run
  2. Deploy for real. Expect == clawlight-led: active == and the same log lines. If the service fails here but the dry run worked, the fault is GPIO access on the Pi, not the wiring. 
    scripts/clawlight/deploy_clawlight_led_pi.sh
  3. Active: green. Give a Claude session something to work on. Red instead of green means the colour legs are swapped — swap the jumpers on pins 33 and 35, not the code. Dark while working and lit when idle means the polarity is inverted (step 4 of the leg test).
  4. Waiting: red. Let the session finish its turn and wait for you. Red alone, no green tint: a green tint means the pins share a wire somewhere.
  5. Unknown, then idle, on demand. Both are hard to catch naturally, so this script stops the server (amber pulse, holding the same hue as it fades), then hand-publishes idle (dim steady amber), then starts the server again and the real colour returns. 
    scripts/clawlight/show_led_states.sh 45
  6. Tune by eye if either looks wrong. Each sweep stops the service, steps through values printed as ready-made lines for clawlight-led.py, and starts it again; paste the one that looks right and redeploy. Bench result, 2026-09-16: AMBER = (0.5, 1.0) — the green die is weak on 220R, so red came down rather than green going up — and IDLE_BRIGHTNESS = 0.3, since 6% read as very dim. 
    scripts/clawlight/tune_led.sh amber
scripts/clawlight/tune_led.sh idle
