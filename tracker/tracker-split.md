# Project tracker: one file per project in tracker/ (PROJECTS.md split)
**Status:** Done

**Why:** `PROJECTS.md` had grown to 4,220 lines / 640 KB across 115 entries by 2026-11-18 (from 3,108 lines / 471 KB on 2026-11-04), with 186 commits in two weeks. By size: Done 44%, Backlog 34%, Active 16%. Logs were only 26% - the bulk was design and research, and the user was unhappy with one ever-growing file.

**Outcome:** 2026-11-18 - every project is its own `tracker/<slug>.md`; `PROJECTS.md` is a generated one-line-per-project index. Format and rules: [`README.md`](README.md).

#### What was decided (2026-11-18, with the user)

| Question | Decision |
|---|---|
| Where projects live | One flat `tracker/` folder, one file per project of every status; files never move, status is one line |
| `PROJECTS.md` | Generated by `tools/repo-tools/tracker.py index`; the pre-commit hook **checks** it, never writes it |
| Header format | Plain `**Status:**` / `**Priority:**` / `**Cost:**` / `**Effort:**` lines, not YAML front matter (four parsers already read that style; macOS python has no YAML) |
| Budget | Required on open projects: Cost in rupees (`₹low-high`), Effort in evenings/weekends. Migrated files got `?`, filled in when touched (hook enforces) |
| Index totals | Rupees totalled for Active and Parked only; Backlog shows a count (most ideas stay ideas, and that is expected) |
| New ideas | Still written by the `idea-dump` agent, now as a new file with a budget |
| Code | Stays in `projects/<name>/`; tracker slug matches the folder name where there is one |

#### Rejected

- **Archive Done/Closed to one file, keep the rest in `PROJECTS.md`** (the 2026-11-04 proposal): halves the file but open entries alone were 330 KB and growing.
- **Short cards in `PROJECTS.md` + detail files only for picked projects:** the user preferred idea-dump writing a full file per idea and the index staying one line each.
- **GitHub Issues / Projects:** the repo is public and issue text skips the commit-time PII scan; no offline access when Airtel is down; the commit hooks, projects-ui and the merged shopping list would all go. Self-hosted trackers (Vikunja, Plane): one more stateful service to back up.
- **A database:** writers are Claude sessions and an editor, and git history is the audit trail.

#### Traps found in the architecture review

- **A hook that stages a file outside a `git commit -- <paths>` list** commits it but leaves a staged revert in the real index (reproduced). Hence: index is check-only, and `fix_open_items.sh` in a pathspec commit fixes the working tree and stops.
- **Generated file across two clones** (xero and the Mac) conflicts on every rebase: regenerate, never hand-merge.
- **`### ` lines inside code fences**: the old file had 2, so a naive split would have made 117 files instead of 115.
- **Moved text trips the PII scan** (old LAN/DNS addresses in the MacBook DNS entry, `pramod@xero.local`): the migration commit was made with `--no-verify` after running the tracker checks by hand.
